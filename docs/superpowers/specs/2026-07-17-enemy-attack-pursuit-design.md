# 敌人攻击追击优化设计

## 背景

当前 `EnemyShouldAttackNodeAsset` 要求玩家已经处于攻击范围，才会进行攻击欲望判定。攻击动作随后立即停止移动并启动攻击，导致敌人无法表现为“决定攻击后主动接近并出手”。

## 目标

将攻击意图决策与攻击距离判定解耦：敌人先决定是否攻击，再追向玩家，进入攻击范围后执行现有攻击流程。

## 设计

### 攻击决策

`EnemyShouldAttackNodeAsset` 仅检查：

- 决策配置存在；
- 攻击冷却已经结束；
- 本次攻击欲望随机判定通过。

攻击范围不再参与意图生成。无论概率通过或失败，仍沿用现有规则消耗本次决策窗口，避免逐帧重复判定。

### 攻击追击

扩展 `EnemySetIntentNodeAsset` 的现有攻击动作：

- 目标有效但未进入攻击范围时，播放移动动画并持续移动到目标，返回 `Running`；
- 进入攻击范围后停止移动，调用现有 `StartAttack`；
- 攻击动画、技能启动和普通连招继续沿用当前实现。

现有 `AttackSequence` 会在攻击条件成功后保持攻击动作，因此不新增行为树节点，也不修改序列化行为树资产。

### 取消规则

尚未出手的攻击追击在以下情况取消，并返回 `Failure` 让行为树重新选择行为：

- 当前目标为空；
- 目标既不可见，也不存在攻击者记忆；
- 目标距离超过 `EnemyDecisionProfile.maxChaseDistance`；
- 敌人死亡、进入受击反应或失衡状态。

实际攻击已经启动后，继续遵守现有 `canInterruptAttack` 和攻击生命周期规则，本次优化不改变动作中断语义。

## 方案取舍

采用“扩展现有攻击动作”，因为它与当前 `AttackSequence` 的运行语义一致，且无需增加资产引用或黑板持久状态。

未采用以下方案：

- 新增独立“攻击接近”行为树节点：职责更细，但需要新增并维护行为树资产和引用。
- 在黑板保存持久攻击意图：可以跨分支保持意图，但会增加所有中断路径的状态清理成本。

## 测试

按 TDD 增加 EditMode 测试：

1. 玩家在攻击范围外时，攻击欲望仍可通过并消耗决策窗口。
2. 攻击动作在范围外返回 `Running`、设置追击目标且不启动攻击。
3. 玩家进入攻击范围后，攻击动作停止移动并进入现有攻击启动流程。
4. 目标丢失、无可见性/记忆或超过最大追击距离时，攻击追击返回 `Failure`。

最终使用 `./.aibridge/cli/AIBridgeCLI.exe compile unity` 编译，并检查 Error 日志。

## 非目标

- 不修改攻击欲望、冷却、攻击范围和最大追击距离的配置值。
- 不修改普通 Chase、Search、Defense、Retreat 等行为。
- 不重构 `Selector` 或 `Sequence` 的抢占机制。
