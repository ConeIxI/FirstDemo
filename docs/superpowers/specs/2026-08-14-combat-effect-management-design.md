# 战斗特效管理框架设计

## 1. 背景

当前技能配置已经包含 `onCastEffects`、`onHitEffects`、`onBlockEffects` 和
`onParryEffects`，`CombatEffectExecutor` 会在战斗结算后根据 `CombatEvent` 直接实例化
Prefab。但是现有实现只支持在命中点设置基础 Transform，不负责攻击动画事件、角色挂点、
跟随、并发控制、生命周期或实例复用。

本设计覆盖攻击动作特效、攻击命中特效和受伤特效。受伤特效由攻击技能决定，不根据目标材质
二次选型。

## 2. 目标

- 攻击动作特效由动画事件精确触发和停止。
- 命中、格挡和招架特效继续由战斗结算结果触发。
- 支持世界命中点、攻击者挂点和受击者挂点，并可选择是否跟随。
- 支持粒子完成、固定时长和动画事件手动停止三种回收方式。
- 支持允许叠加和唯一通道替换两种并发方式。
- 使用按 Prefab 路径划分的懒加载对象池复用实例。
- 公共定义可被多个技能复用，技能可覆盖局部参数。
- 保持战斗数值结算与表现播放解耦。

## 3. 非目标

- 不提供编辑器预览窗口或配置检查窗口。
- 不预热对象池。
- 不按受击者材质、阵营或角色类型选择特效。
- 不修改任何 `.controller` 文件。
- 不新增测试文件或测试代码。
- 不进行 Play Mode 验收。

## 4. 总体架构

### 4.1 CombatEffectConfig

公共特效定义，实现现有配置体系使用的 `IConfig`，由 `ConfigManager` 加载。它只描述一个
可复用特效的默认播放规则，不包含技能 ID 或具体触发时机。

核心数据：

- `effectId`：公共特效唯一 ID。
- `path`：Prefab 资源路径，也是对象池分组键。
- `attachment`：世界命中点、攻击者挂点或受击者挂点。
- `socketName`：选择角色挂点时使用的名称。
- `follow`：生成后是否保持父子关系并跟随挂点。
- `position`、`rotation`、`scale`：默认局部变换。
- `orientation`：配置旋转、攻击者朝向或命中方向。
- `recycleMode`：粒子完成、固定时长或手动停止。
- `duration`：固定时长回收使用的秒数。
- `concurrency`：允许叠加或唯一通道。
- `channel`：唯一通道及手动停止使用的稳定名称。

### 4.2 SkillEffectBinding

技能与公共特效之间的绑定关系，包含：

- `triggerKey`：攻击动画事件使用的稳定触发标识。
- `effectId`：引用公共特效定义。
- 可选的挂载覆盖对象。
- 可选的 Transform 覆盖对象。

覆盖对象不存在时完全使用公共定义。覆盖对象存在时只替换该对象明确承载的字段，避免使用
零向量、空字符串等哨兵值推断配置意图。

`SkillConfig` 最终保留以下四组绑定：

- `attackEffects`：由攻击动画事件触发。
- `onHitEffects`：普通命中后触发。
- `onBlockEffects`：格挡后触发。
- `onParryEffects`：招架后触发。

删除旧 `SkillEffectTrigger`。旧 `onCastEffects` 迁移为 `attackEffects`，不保留两套结构或兼容
分支。命中点特效和受伤者特效都位于 `onHitEffects`，通过各自的挂载规则区分。

### 4.3 CombatEffectService

场景级统一播放服务，是特效实例和生命周期的唯一管理者。职责包括：

- 建立并持有公共特效配置字典。
- 合并公共定义与技能局部覆盖。
- 将播放上下文转换为完整的播放请求。
- 解析世界位置、旋转和父节点。
- 执行并发策略并返回实例句柄。
- 更新固定时长和粒子完成类型的活动实例。
- 将结束的实例交还对象池。

服务不参与伤害、硬直、死亡等战斗判定。

### 4.4 CombatEffectPool

由 `CombatEffectService` 独占，不再暴露第二个全局入口。每个 Prefab 路径对应一个懒加载池：

- 首次请求时通过现有 `ResourceManager` 创建实例。
- 取出时应用统一初始状态和本次播放参数。
- 回收时停止全部子粒子系统、解除父节点、清理实例句柄与通道归属、恢复根节点 Transform，
  然后禁用对象。
- 池不决定实例何时结束，只负责创建、复用和重置。

Prefab 根节点统一按位置零、旋转零、缩放一进行池化重置；特效内部造型偏移由 Prefab 子节点
或配置数据负责，避免池记录运行时变换作为新默认值。

### 4.5 CharacterEffectController

每个战斗角色持有一个控制器，负责角色局部上下文：

- 从当前 `CombatAbilitySystem` 获取正在执行的技能。
- 解析攻击者和受击者的挂点。
- 接收动画事件的播放、停止指令。
- 将角色实例作为所有者传给 `CombatEffectService`，不自行保存活动特效状态。
- 在角色禁用、死亡或销毁时，请求服务回收该所有者的跟随实例和手动生命周期实例。

动画事件只调用两个稳定入口：

- 播放入口接收 `triggerKey`，同一触发标识允许匹配并播放多个绑定。
- 停止入口接收 `channel`，请求服务停止该角色对应唯一通道的活动实例。

动画事件不携带 Prefab 路径、特效 ID 或 Transform 参数。

### 4.6 CombatEffectExecutor

保留为 `CombatEvent` 到特效播放请求的适配层。它根据事件类型选择 `onHitEffects`、
`onBlockEffects` 或 `onParryEffects`，并把攻击者、受击者、命中点和命中方向交给
`CombatEffectService`。它不再加载资源、实例化对象或管理生命周期。

`Invincible` 事件在首版不播放特效。

## 5. 播放流程

### 5.1 攻击动作特效

1. 动画事件向攻击者的 `CharacterEffectController` 发送 `triggerKey`。
2. 控制器读取当前技能的 `attackEffects`，筛选所有匹配绑定。
3. 控制器为每个绑定构造攻击者上下文并调用 `CombatEffectService`。
4. 服务解析公共定义和局部覆盖，从对象池取出实例。
5. 服务按攻击者挂点或世界规则放置并播放实例。
6. 后续动画事件可按 `channel` 手动停止持续特效。

### 5.2 命中与受伤特效

1. `WeaponHitDetector` 报告碰撞和命中点。
2. `CombatAbilitySystem` 完成伤害、格挡、招架等结算并生成 `CombatEvent`。
3. `CombatEffectExecutor` 根据事件类型选取技能绑定列表。
4. 服务可以同时在世界命中点生成刀光或火花，并在受击者挂点生成流血或灼烧效果。
5. 战斗事件的命中方向用于需要沿攻击方向对齐的世界特效。

### 5.3 坐标规则

- 世界命中点：先根据朝向规则计算世界旋转，再以该旋转变换位置偏移，即
  `hitPoint + rotation * positionOffset`。
- 角色挂点且跟随：实例成为挂点子节点，配置位置与旋转按局部空间应用。
- 角色挂点但不跟随：生成瞬间读取挂点世界变换，随后解除父节点并作为世界实例管理。
- `ConfigRotation` 使用配置旋转；`SourceForward` 使用攻击者朝向；`HitDirection` 使用
  `CombatEvent.HitDirection`。
- 攻击动画事件没有受击者和命中方向，因此其绑定不得依赖受击者挂点或命中方向。

## 6. 生命周期与并发

### 6.1 回收策略

- 粒子完成：等待 Prefab 下全部子粒子系统不再存活后回收。
- 固定时长：从实例开始播放起计时，到达 `duration` 后回收。
- 手动停止：必须配置非空 `channel`，仅由停止动画事件、唯一通道替换或角色清理回收。

非粒子 Prefab 不允许使用粒子完成策略，必须选择固定时长或手动停止。

### 6.2 并发策略

- 允许叠加：每次触发都从池中取得独立实例，适用于命中火花等瞬时效果。
- 唯一通道：键为“角色实例 + 通道名”。播放新实例前先回收旧实例，适用于武器拖尾、
  蓄力等持续效果。

唯一通道策略必须配置非空 `channel`。世界命中点的叠加特效不写入角色通道表。

## 7. 错误处理

- 公共配置加载时建立 `effectId` 字典；重复 ID 直接报错并终止特效服务初始化。
- 技能引用未知 ID、空路径或资源加载失败时，记录包含 `skillId`、`effectId` 和 `path`
  的明确错误，本次表现播放失败，但已经完成的战斗结算不回滚。
- 角色挂点不存在时记录明确错误，不自动退回角色根节点。
- 攻击动画事件在没有当前技能时记录包含角色和 `triggerKey` 的错误。
- 手动回收或唯一通道缺少 `channel`、固定时长非正数、粒子回收用于非粒子 Prefab 时，
  记录配置错误并拒绝播放。
- 错误不得静默吞没，也不使用隐式降级掩盖错误配置。

## 8. 迁移策略

1. 新增公共 `CombatEffectConfig` 配置及其加载入口。
2. 用 `SkillEffectBinding` 替换旧 `SkillEffectData`。
3. 将现有路径和 Transform 数据抽取为公共定义，技能绑定引用对应 `effectId`。
4. 将 `onCastEffects` 迁移为 `attackEffects`，为每个攻击动画事件分配稳定 `triggerKey`。
5. 更新命中、格挡和招架配置数组。
6. 删除旧类型、旧字段和 `CombatEffectExecutor` 的直接实例化逻辑。

迁移完成后不保留旧配置读取路径，确保公共定义与技能绑定是唯一真相来源。

## 9. 验收与限制

本阶段不运行 Play Mode，也不新增测试文件或测试代码。验收仅包括：

- 使用 `$CLI compile unity` 验证 Unity 编译。
- 静态检查旧字段、旧类型及其引用已经完全删除。
- 静态检查配置加载、技能绑定、动画事件入口、战斗事件适配和对象池生命周期之间的调用
  关系完整。
- 静态检查所有现有特效配置均已迁移到公共定义和技能绑定。
- 确认没有修改 `.controller` 文件。

由于明确排除 Play Mode，本阶段不能声称动画事件时机、粒子结束检测、角色销毁清理、唯一通道
替换和池实例复用已经通过运行时验证；这些行为只能确认实现和编译层面的一致性。
