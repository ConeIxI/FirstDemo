# 敌人 AI 行为树决策层设计

## 背景

当前项目已有敌人基础结构，包括 `EnemyAgent`、`EnemyBlackboard`、敌人感知、移动、战斗、动画等组件，以及行为树节点资产。新的敌人 AI 决策层采用“行为树 + 可配置规则”方案，继续复用现有敌人模块，不重建独立的战斗框架。

用户确认的基础敌人战斗 AI 状态包括：战斗待机、进攻、受伤、防御、后撤。行为树只负责选择当前意图，具体动作、动画、霸体、受伤、稳定值和伤害结算由已有组件或后续战斗组件执行。

## 目标

- 建立一个可扩展的敌人 AI 决策层，让不同敌人通过行为树组合和参数配置表现出不同战斗行为。
- 支持基础敌人的五个战斗状态：战斗待机、进攻、受伤、防御、后撤。
- 支持攻击欲望、防御率、保持距离、后撤倾向、技能权重等配置。
- 保持行为树节点通用，避免为每个敌人写专属 AI 代码。
- 明确行为树、配置、黑板、组件之间的职责边界。

## 非目标

- 不在第一版引入 GOAP。
- 不在第一版实现复杂群体协同、绕背、召唤、治疗、阵型等高级行为。
- 不把动画帧、霸体、伤害结算、防御稳定值扣减等战斗细节放进行为树节点。
- 不重写现有 Enemy 基础架构。

## 总体架构

```text
EnemyAgent
  ├─ EnemyBlackboard
  ├─ EnemyDecisionProfile
  ├─ BehaviorTree
  ├─ EnemyPerceptionComponent
  ├─ EnemyMovementComponent
  ├─ EnemyCombatComponent
  └─ EnemyAnimationComponent
```

职责划分：

- `EnemyAgent`：敌人运行入口，持有黑板、配置、组件引用和行为树实例。
- `EnemyBlackboard`：保存当前目标、玩家距离、是否受击、是否失衡、当前意图、冷却、短期记忆等运行时事实。
- `EnemyDecisionProfile`：保存敌人决策参数，不同敌人通过不同配置表现差异。
- `BehaviorTree`：读取黑板和配置，决定当前战斗意图。
- `EnemyPerceptionComponent`：更新目标可见性、目标距离、目标方向等感知信息。
- `EnemyMovementComponent`：执行靠近、保持距离、后撤等移动意图。
- `EnemyCombatComponent`：执行攻击、防御、稳定值、受击、打断等战斗行为。
- `EnemyAnimationComponent`：播放待机、攻击、防御、受伤、后撤等动画。

## 决策配置

每种敌人至少绑定一个 `EnemyDecisionProfile`。配置字段建议包括：

```text
attackDesire：攻击欲望，影响待机时进入进攻的频率
defenseRate：防御率，影响待机时进入防御的概率
counterDesire：反击倾向，影响防御或玩家硬直后的反击概率
retreatDesire：后撤倾向，影响距离过近、攻击结束或受伤后的后撤概率
preferredDistance：期望保持距离
minSafeDistance：最小安全距离，低于该距离时可触发后撤
maxChaseDistance：最大追击距离，超过该距离时停止追击或进入搜索
attackCooldown：攻击决策冷却
defenseDuration：防御持续时间
retreatDistance：后撤目标距离
lowStabilityThreshold：稳定值低阈值
availableSkills：可用技能列表
skillWeights：技能权重
lowHealthModifiers：低血量时对攻击、防御、后撤倾向的修正
hitReactionModifiers：受击后对后撤、防御、反击倾向的修正
```

配置差异分三档：

- 参数变化：只新建 `EnemyDecisionProfile`。
- 行为变化：复用节点，重新组合行为树或子树。
- 能力变化：新增通用行为节点或组件能力。

## 黑板数据

行为树依赖黑板事实，不直接查询复杂组件内部状态。黑板建议保存：

```text
target：当前目标
hasTarget：是否有目标
canSeeTarget：是否能看见目标
distanceToTarget：与目标距离
isInAttackRange：是否在攻击距离
isTooCloseToTarget：是否低于最小安全距离
isHitReacting：是否正在受击
isUnbalanced：是否失衡
isDefending：是否正在防御
isRetreating：是否正在后撤
currentIntent：当前决策意图
lastIntent：上一次决策意图
lastAttackTime：上次攻击时间
lastDefenseTime：上次防御时间
lastHitTime：上次受击时间
selectedSkillId：本次选择的技能
```

黑板更新来源：

- 感知组件更新目标、可见性和距离。
- 战斗组件更新受击、失衡、防御、攻击冷却和稳定值状态。
- 行为树写入当前意图和选择的技能。
- 动画或战斗组件在动作结束时清理对应运行状态。

## 基础行为树

基础近战敌人的行为树建议结构：

```text
Root
├─ 强制状态分支
│  ├─ 死亡
│  ├─ 失衡
│  └─ 受伤
├─ 目标判断分支
│  ├─ 无目标 -> 战斗待机或搜索
│  └─ 目标不可见 -> 靠近最后记忆位置或待机
├─ 自保分支
│  ├─ 稳定值过低 -> 后撤
│  ├─ 玩家距离过近且允许后撤 -> 后撤
│  └─ 防御随机判定通过 -> 防御
├─ 进攻分支
│  ├─ 在攻击距离内且攻击冷却结束 -> 选择技能并进攻
│  └─ 不在攻击距离 -> 靠近玩家
└─ 战斗待机分支
   └─ 保持距离、面向玩家、等待下一次决策
```

优先级原则：

- 受伤、失衡、死亡等强制状态优先级最高。
- 后撤和防御属于自保行为，优先级高于普通进攻。
- 进攻由攻击欲望、攻击冷却、距离和技能可用性共同决定。
- 战斗待机是兜底行为，负责保持架势和期望距离。

## 五个基础状态的行为映射

### 战斗待机

行为树表现：

- 让敌人面向玩家并摆好架势。
- 不主动攻击，直到攻击欲望判定或防御判定通过。
- 与玩家保持 `preferredDistance`。
- 玩家远离时靠近玩家。
- 玩家靠近时默认不后退，除非当前敌人配置允许近距离后撤。

可转变为：

- 进攻：攻击欲望判定通过，攻击冷却结束，目标在攻击范围内。
- 防御：防御率判定通过，且当前状态允许防御。
- 受伤：战斗待机期间受到攻击。

### 进攻

行为树表现：

- 根据 `availableSkills` 和 `skillWeights` 选择技能。
- 写入攻击意图和 `selectedSkillId`。
- 攻击执行交给战斗组件和动画组件。

可转变为：

- 后撤：一套攻击结束后按配置进入后撤。
- 受伤：攻击期间受到可打断攻击，且当前攻击没有霸体。

### 受伤

行为树表现：

- 受击事件写入黑板后，强制状态分支优先进入受伤处理。
- 播放受伤或失衡动画由动画组件执行。

可转变为：

- 战斗待机：受伤动画结束且玩家距离不近。
- 后撤：受伤动画结束且玩家距离较近，或配置倾向受击后后撤。

### 防御

行为树表现：

- 防御率判定通过后写入防御意图。
- 防御时长由配置决定。
- 防御期间敌人不受普通伤害，但稳定值下降。

可转变为：

- 受伤：防御期间稳定值归零，进入失衡或受伤表现。
- 战斗待机：防御倒计时结束。

### 后撤

行为树表现：

- 写入后撤意图，由移动和动画组件执行后撤。
- 后撤目标距离来自 `retreatDistance` 和当前目标方向。
- 后撤动画期间为霸体，不允许普通打断。

可转变为：

- 战斗待机：后撤动画结束或后撤距离达成。

## 不同敌人的扩展方式

### 狂战士敌人

通过配置提高攻击欲望、降低防御率、降低后撤倾向、缩短攻击冷却，并提高突进和连击技能权重。行为树优先检查进攻分支，使敌人持续压迫玩家。

### 盾兵敌人

通过配置提高防御率、防御时长、稳定值阈值和反击倾向。行为树可以把“玩家靠近或玩家攻击中 -> 防御”放到进攻前，并在防御后提高反击技能权重。

### 游击敌人

通过配置提高后撤倾向、扩大期望距离，并开启攻击后后撤。行为树优先处理“玩家过近 -> 后撤”，攻击只在短窗口内发生。

### 远程敌人

通过配置提高期望距离和远程技能权重，关闭或降低近战技能权重。行为树优先处理“玩家过近 -> 后撤”和“射程内 -> 远程攻击”。

### 反击敌人

通过配置降低主动攻击欲望，提高防御率和反击倾向。行为树优先处理“玩家攻击中 -> 防御或后撤”和“玩家硬直 -> 反击”。

## 行为树节点设计原则

- 节点尽量通用，不以具体敌人命名。
- 条件节点只判断黑板事实或配置阈值。
- 动作节点只写入意图或轻量黑板字段。
- 复杂执行逻辑放在敌人组件中。
- 随机节点必须使用配置权重，便于不同敌人调参。
- 行为树节点不直接处理伤害数值、动画帧窗口、霸体帧和稳定值扣减。

推荐节点类型：

```text
EnemyHasTargetNode
EnemyCanSeeTargetNode
EnemyIsInAttackRangeNode
EnemyIsTooCloseToTargetNode
EnemyIsLowStabilityNode
EnemyCanAttackNode
EnemyShouldAttackNode
EnemyShouldDefendNode
EnemyShouldRetreatNode
EnemySelectSkillNode
EnemySetIntentNode
EnemyKeepDistanceNode
```

## 数据流

```text
感知组件更新目标事实
        ↓
黑板保存目标、距离、可见性
        ↓
行为树读取黑板和配置
        ↓
行为树写入 currentIntent 和 selectedSkillId
        ↓
移动/战斗/动画组件执行意图
        ↓
组件把执行结果、受击、失衡、冷却写回黑板
```

## 调试与可观测性

第一版应保证能看到以下信息：

- 当前行为树分支。
- 当前 `currentIntent`。
- 当前选择的技能。
- 当前目标距离。
- 攻击、防御、后撤触发原因。
- 上次状态切换时间。

这些信息用于定位“敌人为什么攻击”“为什么防御”“为什么不后撤”等问题。

## 校验规则

配置校验应覆盖：

- 攻击欲望、防御率、后撤倾向等概率值在合法范围内。
- 期望距离不小于最小安全距离。
- 最大追击距离大于攻击距离。
- 防御时长和攻击冷却为正数。
- 技能权重不为负数。
- 可用技能列表为空时，进攻分支不会选择攻击意图。

## 测试策略

编辑器模式测试建议覆盖：

- 基础敌人在待机状态下按攻击欲望进入进攻。
- 基础敌人在待机状态下按防御率进入防御。
- 玩家距离过远时敌人写入靠近或保持距离意图。
- 玩家距离过近时，默认基础敌人不后退。
- 配置允许后撤的敌人在距离过近时写入后撤意图。
- 稳定值低于阈值时自保分支优先于进攻分支。
- 攻击冷却未结束时不进入进攻。
- 技能权重选择能返回合法技能。
- 无目标时不进入攻击或防御。

Unity 验证必须使用 `$CLI compile unity`。`compile dotnet` 只能作为额外检查，不能替代 Unity 编译。

## 验收标准

- 基础敌人可以通过行为树和配置完成战斗待机、进攻、受伤、防御、后撤五类决策。
- 新增参数差异型敌人不需要新增代码，只需要新增配置。
- 新增行为差异型敌人优先通过复用节点和组合行为树完成。
- 新增能力型敌人只新增通用节点或组件能力，不写敌人专属节点。
- 行为树节点不承担动画、霸体、伤害和稳定值结算。
- 决策过程可通过黑板和调试信息追踪。
